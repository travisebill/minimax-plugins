ICC Profiles

The International Color Consortium (ICC) was formed in the early 
1990s to address the problem of color management in printers, displays, 
scanners, operating systems, applications, servers, in an open, industry-
standard manner. This work resulted in the ICC Specification, which 
defines methods for color management that are based on objects called 
ICC profiles.
ICC profiles are created for input and output devices by their 
manufacturer and are essentially look-up-tables (LUTs) that specify how 
to convert between the color space of the device, e.g. a specific RGB for 
a display (input color), or a specific CMYK for a printer (output color), 
and a standard device-independent color space called the Profile 
Connection Space (PCS). The color spaces used for the PCS are CIE 
Lab and CIE XYZ.

This conversion to/from PCS via ICC profiles allows colors to be
accurately passed from input devices to output devices.

The AFP Color Management Resource (CMR)

(cid:137) ICC profiles are the industry-standard for color management and  
form the basis for color management in AFP; they are integrated 
into AFP as resources that are called AFP Color Management 
Resources (CMRs)

• AFP CMRs are:

• Defined in a new formal architecture under the AFP Architecture umbrella –

the Color Management Object Content Architecture (CMOCA)

• Processed as AFP resources – installed, downloaded, activated, captured, 

re-used 

• Can be associated with a MO:DCA document component:

• Printfile
• Document
• Group of pages/sheets
• Page or overlay
• Data object

AFP Color Consortium

<<<PAGE 10>>>
CMR Types

(cid:137) Color Conversion (CC) CMRs: Contain ICC profiles (in their ICC-
defined syntax) that convert a device-specific color to/from the 
device-independent ICC Profile Connection Space (PCS)

(cid:137) Tone Transfer Curve (TTC) CMRs: Transfer curves that are used 

to modify the values of a particular color component

(cid:137) Halftone (HT) CMRs: Screens that are applied to multi-bit data

(cid:137) Indexed (IX) CMRs: Mappings of indexed colors in the data stream 

to output device colors or colorant combinations 

(cid:137) Link Color Conversion (LK) CMRs: Look-up tables (LUTs) that 

convert directly from a device-specific input color space in the data 
to the device-specific output color space of the presentation device

10

AFP Color Consortium

<<<PAGE 11>>>
CMR Processing Modes

(cid:137) Audit: An audit CMR specifies color-management processing that has 
been done on a document component; for example, it may specify a 
color conversion that has been done on the data

(cid:137) Instruction: An instruction CMR specifies color-management 

processing that is to be done on a document component; for example, 
it may specify a halftone that is to be applied to multi-bit data

(cid:137) Link: A link CMR is used to link an input color space in the presentation 

data directly to the output color space of the presentation device 
(without going through the PCS)  

The processing mode is not part of the CMR; it is specified in the 
context in which the CMR is associated with a document component, 
e.g., on the structured field that references the CMR.

CMR Creation and Installation: CMR Installer and 
CMRE

(cid:137) CMRs are installed as resources in an AFP resource library with a 
workstation-based CMR Installer that is part of a new Resource 
Installer. The CMR Installer:
(cid:131) uploads the CMR into the resource library of a print server
(cid:131) builds the CMR Resource Access Table (RAT) entry that maps the CMR 
name to a file name, to an object-OID, and optionally to other CMRs

(cid:137) CMRs are created by the CMR Engine (CMRE), which runs in 

conjunction with the Resource Installer to:
(cid:131) Generate Color Conversion (CC) CMRs from ICC profiles, including profiles 

that were copied/extracted from data objects

(cid:131) Generate Halftone (HT), Tone Transfer Curve (TTC), and Indexed (IX) 

CMRs from input data

(cid:131) Generate Link Color Conversion (LK) CMRs that convert the input color 

space defined in an audit CC CMR to the output color space of configured 
presentation devices

Inline CMRs

(cid:137) CMRs may also be carried in a printfile-level resource group in a BRS -

BOC/EOC – ERS container, and are then called inline CMRs
(cid:131) BRS specifies CMR name
(cid:131) For inline Color Conversion CMRs, BRS may specify Link Color Conversion CMRs

that convert directly to output color spaces of different target devices

(cid:131) For inline generic Halftone or Tone Transfer Curve CMRs, BRS may specify device-

specific HT or TTC CMRs; such CMRs are used in place of the inline generic CMR if 
the device type and model match the target device

Associating CMRs with a MO:DCA document 
component

(cid:137) CMRs can be associated with document components at all levels of the

MO:DCA document hierarchy:
(cid:131) Printfile (highest)
(cid:131) Document
(cid:131) Group of pages/sheets
(cid:131) Page/overlay
(cid:131) Data object (lowest)

(cid:137) A CMR at a lower level always overrides – for that document component 

only – a conflicting CMR at a higher level
(cid:131) Example: CC CMR at printfile level defines RGB = scanner (y) RGB, CC 

CMR at page (n) level defines RGB = scanner (x) RGB. According to rule, 
since CC CMRs conflict, all RGB for page (n) is interpreted as scanner (x) 
RGB

User Input: Rendering Intent

(cid:137) The ICC defines four rendering intents to specify how out-of-gamut 
colors should be mapped to in-gamut colors; each may produce a 
different output appearance:
(cid:131) Perceptual: Tries to preserve appearance by maintaining color relationships; typically 

used to render continuous-tone images 

(cid:131) Saturation: Tries to generate vivid, saturated colors, even at the expense of color 

accuracy; typically used for business graphics

(cid:131) Media-relative colorimetric: Maps white point of source color to white point of output 
media; colors ‘look right’ but may not be accurate colorimetrically. Typically used for 
vector graphics or images.
ICC-absolute colorimetric: Does not map white point of source color to white point 
of output media. If source white is bluish and media white is yellowish, system adds 
cyan to simulate blue on output medium. Colors are accurate colorimetrically but may 
not ‘look right’. Typically used for logos or  proofing.

(cid:131)

(cid:137) To properly process Color Conversion CMRs and Link Color Conversion 

CMRs, the system needs to know the end user’s rendering intent

CMR Resource Access Table (RAT)

(cid:137) When CMRs are installed in resource libraries, they are processed using a CMR 

Resource Access Table (RAT)
(cid:131) RAT concept first introduced in AFP with TrueType/OpenType fonts
(cid:131) Architected structure defined in the MO:DCA reference (SC31-6802)

(cid:137) Allows CMRs to be referenced in data stream by their inherent, native name, 

not by a platform-specific file name
(cid:131) Data stream is platform-independent
(cid:131) Mapping to platform-specific file name, to object-OID, and to other processing 

information accomplished via RAT

(cid:137) CMR RAT is located in same library as CMRs
(cid:137) RAT consists of repeating groups (RGs)

(cid:131) One repeating group for each CMR in library
(cid:131) Repeating group is indexed with CMR name from data stream

Usage scenario: least amount of work

defined using audit CC CMRs
(cid:131) If all colors created by same device, e.g. same scanner or same digital

level in the FormDef (as an audit CMR)

(cid:131) If differently-sourced colors at different levels of the hierarchy, need to 
associate appropriate CC CMRs as audit CMRs with those document 
components

(cid:137) Don’t specify instruction CMRs – let the output device select the

Usage scenario – tuned, consistent output

(cid:137) Reference generic instruction TTC/HT CMRs in data stream; output
devices will make reasonably consistent adjustment to the output.
Example: Specify following generic CMRs as instruction CMRs for printfile in 

FormDef:

Generic HT CMR = 106 lpi
Generic TTC CMR = Highlight Midtone

Each output device will apply device-specific CMRs that simulate the 
requested output appearance
