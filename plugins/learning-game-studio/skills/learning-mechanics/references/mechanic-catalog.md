# 機制目錄（learning-mechanics）

12 個機制，依「教學價值 ÷ 風險」大致排序。每個機制都標了它**獎勵什麼行為** —— 這是選機制時最重要的欄位。

數值門檻（回饋時長、通過率）是**經驗值**，不是研究結論；請以實際試玩結果覆蓋它們。

## 型態 → 首選機制

| 學習目標型態 | 首選 | 次選 |
|---|---|---|
| 表徵轉換 | M1 配對 | M12 沙盒 + 任務卡 |
| 概念邊界 | M2 分類歸位 | M5 建造組裝 |
| 程序性 | M3 步驟重組 | M6 路徑規劃 |
| 量感 | M4 估算下注 | M1 配對 |
| 整合應用 | M8 Boss 綜合關卡 | M6 路徑規劃 |
| 動機鋪陳（進入章節前） | M9 探索解鎖 | M10 收集圖鑑 |

---

## M1 配對 / 連連看

- **互動**：兩欄（或場上散落卡片）之間建立連結，一對一或多對一
- **適用型態**：表徵轉換（公式 ↔ 圖形、名詞 ↔ 定義、單位 ↔ 量）
- **獎勵的行為**：辨識與連結
- **教學正確性風險**：只練「認得」不練「推得出」；隨機出題可能出現多解或無解
- **緩解**：出題前機械驗算「存在完美配對且答案集合明確」；配對完成後要求一句理由才能得分
- **不適合**：需要多步推導的目標
- **實作**：A = SVG 連線層 + pointer events；B = Vue 元件 + 狀態機 action（配對狀態不可只存在 DOM）
- **驗收訊號**：首次通過率 70–80%；錯配集中在同一概念 = 講解有漏洞，回去補講解而不是加強動畫

## M2 分類歸位

- **互動**：把元素拖進 2–3 個桶（是 / 不是、屬於 A / 屬於 B）
- **適用型態**：概念邊界
- **獎勵的行為**：抓判準、找出反例
- **教學正確性風險**：**邊界例題寫錯就是直接教錯**；課綱用語與數學定義不一致時會誤導
- **緩解**：只用無爭議例題；每個桶至少一個「幾乎會錯但確定屬於此桶」的關鍵例；爭議例題直接不用
- **不適合**：判準本身還在建立中的章節（會變成猜老師喜好）
- **實作**：A = 拖放 + HTML5 DnD 或 pointer events；B = 拖放元件 + action 記錄每次歸位
- **驗收訊號**：錯誤集中在邊界例題＝判準講解不足；錯誤集中在明顯例題＝互動設計有問題

## M3 步驟重組

- **互動**：把打散的步驟排回正確順序
- **適用型態**：程序性知識
- **獎勵的行為**：掌握順序與依賴關係
- **教學正確性風險**：**很多程序有多條等價路徑**（解一元一次方程式可先移項也可先去括號）
- **緩解**：接受所有等價順序，或明確標示「本題要求課綱標準作法」並在講解中說明為何另一條也對
- **不適合**：步驟間無嚴格依賴的內容（排序會變成主觀）
- **實作**：A = pointer events 拖曳排序；B = 元件 + 狀態機（記錄每次移動，供隱性評量）
- **驗收訊號**：出現「排對了但被判錯」＝等價路徑沒處理，屬零容忍錯誤，必修

## M4 估算下注

- **互動**：先估一個值（或選區間），再下注信心；結果揭露後結算
- **適用型態**：量感（數量級、估算、合理性）
- **獎勵的行為**：精確估算 + 誠實校準信心
- **教學正確性風險**：容易退化成「亂猜也有分」；也可能養成賭博式心態
- **緩解**：結算必須**同時**看準確度與信心校準（估準且高信心才滿分）；不要用隨機賠率
- **不適合**：需要精確答案的章節
- **實作**：A = 區間滑桿 + 數值面板；B = 元件 + 記錄 (估值, 信心) 對用於隱性評量
- **驗收訊號**：若「亂猜」的期望得分接近認真估 → 計分要重設計

## M5 建造組裝

- **互動**：拼出結構（力圖、電路、方程式配平、流程圖）
- **適用型態**：概念邊界 + 結構關係
- **獎勵的行為**：理解元件間的約束關係
- **教學正確性風險**：**拼出正確外觀但不懂**（照著試誤就能過）
- **緩解**：過關條件加入「預測下一步會發生什麼」或要求解釋；試誤次數要能回報
- **不適合**：目標本身不涉及結構
- **實作**：A = SVG / Canvas + 吸附；B = 元件 + 狀態機驗證合法性
- **驗收訊號**：試誤次數過高仍能過關 → 關卡變成暴力解，需加約束

## M6 路徑規劃（解題才能前進）

- **互動**：地圖上有多條路，每條路口要解對一題才能通過
- **適用型態**：程序性 + 整合應用（也適合探索式動機）
- **獎勵的行為**：逐步推理、選擇路線
- **教學正確性風險**：變成走迷宮而非思考；路線選擇若與知識無關就是純裝飾
- **緩解**：每個路口都必須有明確數學 / 科學判準；不同路線對應不同知識點，不是隨機
- **不適合**：單一概念的短章節（成本太高、收益太低）
- **實作**：A = SVG 地圖 + 狀態節點；B = 狀態機的 scene/action（ArcanaArk 主軸）
- **驗收訊號**：玩家能通過卻說不出用了哪個知識點 → 判準沒綁進機制

## M7 限時挑戰

- **互動**：計時完成一批題目或操作
- **適用型態**：**只有** 已學會之後的流暢度訓練（乘法表、單位換算、元素符號）
- **獎勵的行為**：速度與自動化
- **教學正確性風險**：**放在理解階段會訓練焦慮與猜測，直接違反學習目標**（硬性禁止）
- **緩解**：只在複習 / 流暢度區出現並明確標示用途；時間到不等於失敗，只影響分數；永遠提供關閉計時的選項
- **不適合**：任何理解階段
- **實作**：A = 計時器 + 進度條；B = 元件 + 狀態機時間欄位
- **驗收訊號**：關掉計時後答對率顯著上升 → 這個內容還在理解階段，限時要移走

## M8 Boss 綜合關卡

- **互動**：多階段挑戰，每階段考一個知識點；失敗不是歸零
- **適用型態**：整合應用（章末）
- **獎勵的行為**：整合與堅持
- **教學正確性風險**：一次考太多 → 失敗挫折；也可能變成純血量消耗戰
- **緩解**：分階段（每階段 = 一個知識點，答對則該階段結束）；失敗時顯示「是哪個知識點卡住」；提供重試不降 XP 的機制
- **不適合**：章節內的小概念（用 M1–M4 就好）
- **實作**：A = 階段狀態 + 進度條；B = 狀態機 scene + 分階段 action
- **驗收訊號**：卡關集中在同一階段 → 那個知識點要回去補講解，不是調難度

## M9 探索解鎖

- **互動**：在地圖上探索，抵達 / 觸發後解鎖內容與練習關卡
- **適用型態**：動機鋪陳（進入章節前），適合 RPG 型網站
- **獎勵的行為**：主動搜尋、好奇心
- **教學正確性風險**：探索成本 > 學習收益（走很久只為看一句話）；也可能讓學生跳過必要內容
- **緩解**：探索路徑要短、每次互動都有明確知識收穫；解鎖**練習**可以，**跳過學習**不行
- **不適合**：內容本身沒有空間性的主題
- **實作**：A = SVG 地圖 + 熱點；B = 狀態機 + 路由（ArcanaArk 的 world map）
- **驗收訊號**：平均探索時間 vs 知識點數 → 若「每分鐘學到的東西」低於線性閱讀，砍探索

## M10 收集圖鑑

- **互動**：收集元素 / 卡牌 / 成就，可回顧
- **適用型態**：長期動機（跨章節）
- **獎勵的行為**：持續回來、覆蓋面
- **教學正確性風險**：變成無腦刷；收集物與掌握度無關時會誤導學生自評
- **緩解**：**收集物 = 掌握度證據**（例：某知識點答對率達標才解鎖該卡），並讓學生看得到自己缺什麼
- **不適合**：單章網站（沒有長期可言）
- **實作**：A = 進度物件 + 展示頁；B = store + 展示元件
- **驗收訊號**：收集完成度與測驗成績的相關性 → 若無相關，收集物只是裝飾

## M11 對戰（非同步 vs AI / 自我最佳）

- **互動**：解題對抗，比分或回合制
- **適用型態**：整合應用 + 動機
- **獎勵的行為**：在壓力下穩定推理
- **教學正確性風險**：輸贏焦慮、抄答案、把注意力從「懂」移到「贏」
- **緩解**：計分以**解題品質與說明**為主而非速度；非同步對戰（跟自己的最佳紀錄或 AI）避免即時壓力；提供無對戰路徑
- **不適合**：理解階段、低自信學生為主的班級
- **實作**：A = localStorage 最佳紀錄 + 分數比對；B = store + 非同步紀錄
- **驗收訊號**：對戰開啟後錯誤率上升且重試率下降 → 壓力在傷害學習，關掉

## M12 沙盒 + 任務卡

- **互動**：開放式模擬環境，但用任務卡給目標
- **適用型態**：表徵轉換、探索式理解
- **獎勵的行為**：實驗、建立自己的心智模型
- **教學正確性風險**：**無目標的沙盒 = 學不到東西**；模擬若簡化了真實條件卻沒標註就是教錯
- **緩解**：每個沙盒都附 3–5 張任務卡（難度遞增），任務卡要有明確完成判準；簡化處必標「這是直覺版」
- **不適合**：需要精確程序訓練的內容
- **實作**：A = SVG / Canvas + 參數面板；B = 元件 + store
- **驗收訊號**：學生能完成任務卡卻說不出原理 → 任務卡要加「為什麼」追問
